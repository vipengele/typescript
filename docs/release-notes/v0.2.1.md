# v0.2.1

A new resilience package (typed errors, timeout and retry), a much larger logger in
`@vipengele/ts-core-observability` (processors, formatters, a console sink, configuration sources
and lazy attributes), and `LocalDateTime` segments with opt-in seconds. Everything is additive;
nothing is breaking.

## core

- `@vipengele/ts-core-resilience` — **new package.** Resilience primitives for the browser and
  Node 24+, in three entry points: `./timeout` (`createTimeout`, a `TimeoutPolicy` that abandons an
  attempt after `durationMs` and aborts its `signal`), `./retry` (`createRetry`, the backoff
  strategies such as `exponentialBackoff` and `withJitter`, and a `RetryPolicy`) and `./errors` (the
  errors the package raises, such as `OperationTimeoutError`, each with a `code` and a type-guard).
  Every policy has a `name`, `execute(op, options?)` and an `events` stream. The root re-exports
  all three. It depends on `@vipengele/ts-core-common`.

  ```ts
  import { createRetry, exponentialBackoff, withJitter } from "@vipengele/ts-core-resilience/retry";

  const retry = createRetry("profile.fetch", {
    maxAttempts: 4,
    backoff: withJitter(exponentialBackoff({ initialMs: 100, maxMs: 5_000 }), "full"),
  });
  ```

- `@vipengele/ts-core-common`
  - `./types/date-time`
    - `LocalDateTime#segments(locale?, { seconds? })` returns the locale's date-time pattern as
      `DateTimeSegment[]`, for an input that lays out its own fields; joining the values gives
      exactly what `format` writes. `DateTimeSegment` and `DateTimeSegmentType` are exported.
    - `LocalDateTime#format`, `parseLocalized` and `tryParseLocalized` take `{ seconds: true }`
      to write and read a two-digit second after the minute, as `LocalTime` already does. Called
      without options they behave exactly as before: hour and minute only.
- `@vipengele/ts-core-redaction` — no change.
- `@vipengele/ts-core-observability`
  - `./logger`
    - **Processors.** A `LogProcessor` is `(record) => LogRecord | null`: it returns the record to
      pass on or `null` to drop it. `builder.addProcessor(p)` runs ahead of every sink;
      `builder.addSink(sink, { processors: [p] })` runs ahead of that sink only. A processor that
      throws or returns something that is not a record drops the record (fail closed), and what it
      returns is re-normalized, bounded and frozen. `redactionProcessor(policy)` applies a
      different redaction policy to one sink. Built-in redaction still runs first.
    - **Failing sinks are reported once.** The default `onSinkError` warns once per failing sink
      or processor per configuration instead of on every record; a provider with its own
      `onSinkError` still receives every failure, with the failing source as the second argument.
    - **Formatters and a console sink.** `createConsoleSink({ formatter?, console?, source? })`
      writes each record to the console by level. Without a `formatter` it picks one by runtime
      capability: `browserFormatter` (`%c` styling), `ansiFormatter` (one coloured terminal line)
      or `jsonLinesFormatter` (one JSON object per line). A `Formatter` of your own returns the
      arguments of one console call and must not hand user text to the first argument unescaped.
    - **Configuration sources.** A level spec now reaches the logger from the defaults, builder
      sources (`addLevels`, `addSpec`, `addBrowserSources`), live overrides and the `VPG_LOG`
      environment variable, each layer replacing the one below it per category. `VPG_LOG` is read
      once, lazily, and `builder.ignoreEnvironment()` opts out. `addBrowserSources({ urlParameter?,
      storageKey? })` reads a spec from the URL (`?log=`) and `localStorage` (`vipengele.log`).
    - **Console handle.** `Logging.installConsole(name)` puts a function on `globalThis[name]` for
      changing levels live from the browser console, and returns the function that removes it.
    - **Lazy attributes.** Either `attributes` argument of a log call, and `log.with(...)`, may be
      a function (`AttributesThunk`) computed only when the record is written: after the level and
      sink checks, once however many sinks receive it, and before redaction. A thunk that throws
      or returns a non-record gives `{}` and the record is still written. A disabled call
      allocates and runs nothing.

## ts

- `@vipengele/ts` re-exports `DateTimeSegment` and `DateTimeSegmentType`, alongside the date-time
  surface `v0.2.0` listed. `LocalDateTime#segments` and the `seconds` option come with the
  `LocalDateTime` it already exports. It pins the two core packages it depends on at exactly
  `0.2.1`. It does not re-export `@vipengele/ts-core-resilience`.

## Upgrading

Install `0.2.1` of any package; install the observability, common and resilience packages at the
same version. No code change is needed. The one visible difference for an existing logger setup is
that a failing sink is now warned about once rather than on every record.
