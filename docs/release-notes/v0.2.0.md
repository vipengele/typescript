# v0.2.0

Locale-aware time segments and day-period labels on `LocalTime`, configurable size limits for
serialized errors and for the reporter's events, and one change to the reporter's default output
(marked below). Nothing is breaking in the API.

## Changed defaults

- **The reporter bounds an event's message and stack frames by default.** An event whose `message`
  is longer than 8192 UTF-16 code units now carries it cut and suffixed with `"…[truncated]"`, and
  an exception link with more than 100 stack frames keeps its first 100 (the throw site first),
  with no marker entry. Both limits can be raised or turned off with `ReporterBuilder#limits` (see
  `@vipengele/ts-core-observability` below); pass `Infinity` to remove one. Attribute and
  exception-chain bounds are unchanged.

## core

- `@vipengele/ts-core-common`
  - `./types/date-time`
    - `LocalTime#segments(locale?, { seconds? })` returns the locale's time pattern as
      `TimeSegment[]`, each an `hour`, `minute`, `second`, `dayPeriod` or `literal` with its
      `value`, for a time input that lays out its own fields. The segments follow the locale's
      order (`ko-KR` and a 12-hour `ja-JP` put the day period first), a 12-hour hour is
      `hour % 12 || 12`, a 24-hour locale has no `dayPeriod` segment, and joining the values gives
      exactly what `format` writes. `TimeSegment` and `TimeSegmentType` are exported beside
      `DateSegment` and `DateSegmentType`.
    - `LocalTime.dayPeriods(locale?)` returns the locale's `{ am, pm }` labels, the same text
      `format` writes and `tryParseLocalized` accepts. A 24-hour locale returns its 12-hour labels.
    - `LocalTime#format`, `parseLocalized` and `tryParseLocalized` take `{ seconds: true }` as a
      third argument to write and read a two-digit second after the minute, with the locale's own
      separator. With it, a string without a second is rejected; without it, a string with a second
      is rejected, as before. Called without options they behave exactly as before, and
      `LocalDateTime` is still localized to hour and minute.

      ```ts
      import { Locale, LocalTime } from "@vipengele/ts";

      const us = new Locale("en-US");
      const time = LocalTime.of(15, 30, 15);

      time.segments(us, { seconds: true });
      // hour "03", literal ":", minute "30", literal ":", second "15", literal " ", dayPeriod "PM"
      time.format(new Locale("de-DE"), { seconds: true }); // "15:30:15"
      LocalTime.dayPeriods(us); // { am: "AM", pm: "PM" }
      ```

  - `./serialization` and the root — `serializeError(value, options?)` takes a
    `SerializeErrorOptions` (also exported). Besides `maxDepth`, `maxBreadth` and `maxStringLength`,
    it accepts `maxLinks` (the `cause` links followed, default 5) and `maxErrors` (the `errors`
    entries kept per aggregate, default 100). Omitting the options gives the output of `0.1.0`. The
    options are not validated: a `NaN` or non-positive limit is used as given.
- `@vipengele/ts-core-redaction` — no change.
- `@vipengele/ts-core-observability`
  - `./errors` — `ReporterBuilder#limits({ maxDepth, maxBreadth, maxStringLength, maxLinks,
    maxErrors })` sets the bounds the reporter applies to an event's attributes, exception chain,
    stack frames and message. Each is a positive integer or `Infinity`; anything else throws a
    `ReporterConfigError` (`isReporterConfigError`, code `observability.errors.config`). Unset
    limits use the defaults `6`, `100`, `8192`, `5` and `100`; `maxBreadth` also caps the frames of
    one exception link, and `maxStringLength` the event message.
  - It needs the `serializeError` options of `@vipengele/ts-core-common` `0.2.0`; the two are
    released together.

## ts

- `@vipengele/ts` re-exports `TimeSegment` and `TimeSegmentType`, alongside the date-time surface
  `v0.1.0` listed. `LocalTime#segments`, `LocalTime.dayPeriods` and the `seconds` option come with
  the `LocalTime` it already exports. It pins the two core packages it depends on at exactly
  `0.2.0`.

## Upgrading

Install `0.2.0` of any package; install the observability and common packages at the same version.
If you report errors with a message longer than 8192 code units or a stack deeper than 100 frames
and want them whole, call `builder.limits({ maxStringLength: Infinity, maxBreadth: Infinity })`.
