- The Resource has eleven reserved keys (`root.ts` `RESOURCE_KEYS`): release is `service.version`, environment `deployment.environment.name`, dist `service.dist`; `process.runtime.name/version`, `os.type/version`, `browser.name/version` and `device.type` are detected. `service.dist`, `browser.name`, `browser.version` and `device.type` are vipengele extensions, not OpenTelemetry names. None is a `ReporterBuilder` option: a builder method that called `Scope.setResource` would mutate realm-wide state per reporter and two reporters would overwrite each other (ADR-0016 `Considered options`).
- `createReporter` (`reporter.ts` `fillRuntimeContext`) runs `detectRuntimeContext` (`runtime-context.ts`, not exported from `./errors`) once and writes only keys whose current Resource value is `undefined`, inside a try/catch, so an explicit `Scope.setResource` before or after wins and a throwing detector never breaks construction. A logger-only application creates no reporter and gets no detected values. Every `createReporter` call in a test therefore writes detected keys into the realm root; tests that need an all-undefined Resource reset the `Symbol.for("vipengele:scope:attributes")` bag.
- The detector reads `process` only for node, bun, deno and edge, and `navigator.userAgent` (plus synchronous `userAgentData`) elsewhere; Bun and Deno take `process.runtime.version` from `Bun.version` / `Deno.version.deno`; `os.type` is OTel-lowercase (`darwin` for macOS in a browser as on Node). Chromium freezes the UA OS version and iPadOS sends a Mac UA, so `os.version` and `device.type` are best-effort.
- `pipeline.ts` `createCapture` reads `eventResource()` once, before normalize, gates on `isEnvironmentEnabled`, and passes that same Resource through `deliver` to `transport.send`; a `setResource` during the stages no longer reaches that event. An unset environment, including a throwing `Scope.resource()` (swallowed into an all-undefined Resource), is enabled; `""` is a set value.
- `ReporterBuilder.enabledEnvironments` (`builder.ts`) throws `ReporterConfigError` for an empty list or a non-string entry and leaves the builder unchanged, unlike Bugsnag's `enabledReleaseStages: []`. The gate drops the report, not the exit: `globalHandlers`' `exit` policy ignores what capture returns. `createReporter` still hard-codes `processors: []` and `filters: []`.
